Manufacturing System-wide Balanced Random Survival Forest

An interactive walkthrough of Bukkapatnam, Afrin, Dave & Kumara (2019), CIRP Annals — Manufacturing Technology — taking Balanced Random Survival Forests out of the hospital and onto the factory floor, to predict machine breakdowns up to a full shift in advance.

CIRP Annals 2019 Builds on arXiv:1803.09177 (BRSF)

1. The Problem Why Factories Need This

Plant floor systems generate huge volumes of equipment status logs ("up"/"down"/"wait"). Machine breakdowns cause substantial throughput loss in industries like automotive manufacturing. The core question this paper asks:

"Given everything happening across the whole system right now, how much longer until this machine breaks down?"

This is a survival analysis question — but with a critical new wrinkle versus the original BRSF paper: a machine's breakdown risk depends not just on its own history, but on every other machine's status, because of shared material flow and cascading faults across the line.

2. Building the System-wide State Vector The Near-Markovian Trick

Key modeling assumption: once a machine is restored from a fault, its next breakdown depends mostly on (a) how long it's been running since restoration, and (b) the fault status of other machines right now — not on the machine's entire deep history. This near-Markovian assumption is what makes the problem tractable.

Drag the time cursor across three machines' up/down logs and watch the state vector get extracted live at that instant.

—
State vector at time t: $x_i = [\text{status}_1,\dots,\text{status}_{20},\; \Delta t_1,\dots,\Delta t_{20}]$ where $\Delta t_m$ = time since machine m's last restoration. Observed time $T_i = \min(T_i', T_C)$, capped at whichever decision horizon $T_C$ you're prognosing over.

3. The RSF Core, Recapped Same Engine, New Fuel

MBRSF reuses the exact tree-growing machinery from the original BRSF paper. Only the input (system-wide state vectors instead of biomarkers) and the output horizon (breakdowns instead of mortality) change.

Split criterion (log-rank)

At every node, split on predictor $x^r$ and threshold $\gamma^r$ to maximize how differently the two daughter nodes' hazard functions look — identical to the original BRSF.

Leaf hazard estimate

$$ \hat H_h(t|x) = \sum_{t_{l,h}\le t} \frac{d_{l,h}}{Y_{l,h}} $$

Nelson-Aalen estimator — same formula, now estimating "breakdown risk" instead of "mortality risk."

Stopping rule unchanged: every leaf must retain at least $d_0$ unique breakdown events. That's exactly the rule whose interaction with class imbalance the original BRSF paper proved biases hazard estimates — which is why balancing matters here too.

4. Imbalance in Factory Data Over 90% Innocuous

Over 90% of fault events are short, harmless blips. The catastrophic breakdowns that matter for prognosis are rare — an even more extreme imbalance than the mortality dataset in the original paper. SMOTE is applied identically: interpolate synthetic minority (catastrophic breakdown) state vectors between real ones and their nearest minority neighbors.

5. The Theoretical Guarantee Same Proof, Restated

The paper carries over the original BRSF proposition essentially unchanged, just relabeled for breakdown episodes:

$$ \rho'(t) = \rho(t)\,\frac{m_1+m_2}{m_1+m_2'}\cdot \frac{(m_2'-d_0)e^{-2\hat H_2'(t)} + d_0 e^{-2\hat H_1(t)} + m_1(1-e^{-\hat H_1(t)})^2} {(m_2-d_0)e^{-2\hat H_2(t)} + d_0 e^{-2\hat H_1(t)} + m_1(1-e^{-\hat H_1(t)})^2} $$

Adding $(m_2'-m_2)$ synthetic breakdown samples provably reduces the Brier score $\rho(t)$ — balancing helps before you even run the experiment, not just empirically after the fact.

This is the same corollary from the original BRSF paper — the contribution here is showing the proof transfers cleanly to a completely different domain and feature space, not deriving a new theorem.

7. The Hazardogram This Paper's Signature Visualization

A genuinely novel contribution: instead of one hazard curve, plot survival probability $1-\hat H(t)$ as a color map across both episode time (x-axis) and prediction horizon (y-axis). 8. Cross-Machine Influence Graph Variable Importance, System-wide

Variable importance is measured by how much prediction error increases when a variable is randomly permuted: $V_r = e(\tilde x_r) - e(x_r)$. Applied across all 20 machines, this produces a directed graph of which machines' state variables influence which other machines' breakdown risk.

9. Implement It Yourself Adapting BRSF to Multi-Machine Systems

import numpy as np
from sksurv.ensemble import RandomSurvivalForest
from sklearn.neighbors import NearestNeighbors

def build_system_state(machine_logs, t, n_machines=20):
    """
    Near-Markovian state vector at time t, across the whole system.
    machine_logs[m] = sorted list of (timestamp, status) tuples for machine m,
    status: 1 = running, 0 = down/faulted.
    """
    status_vec, dt_vec = [], []
    for m in range(n_machines):
        log = machine_logs[m]
        times = [r[0] for r in log]
        idx = np.searchsorted(times, t, side="right") - 1
        status = log[idx][1] if idx >= 0 else 1
        status_vec.append(status)

        # last restoration = most recent transition 0 -> 1 at or before t
        last_restore = 0.0
        for k in range(idx, 0, -1):
            if log[k][1] == 1 and log[k-1][1] == 0:
                last_restore = log[k][0]
                break
        dt_vec.append(max(t - last_restore, 0.0))
    return np.array(status_vec + dt_vec)


def survival_smote(X_min, T_min, k=5, n_synth=100):
    """SMOTE adapted for survival time (same open design choice as in BRSF)."""
    nn = NearestNeighbors(n_neighbors=k+1).fit(X_min)
    _, nbrs = nn.kneighbors(X_min)
    X_syn, T_syn = [], []
    for _ in range(n_synth):
        i = np.random.randint(len(X_min))
        j = nbrs[i, np.random.randint(1, k+1)]
        g = np.random.uniform(0, 1)
        X_syn.append(X_min[i] + g * (X_min[j] - X_min[i]))
        T_syn.append(T_min[i] + g * (T_min[j] - T_min[i]))
    return np.array(X_syn), np.abs(np.array(T_syn)), np.ones(n_synth, dtype=bool)


def train_mbrsf(X, T, delta, minority_mask, decision_horizon, target_ratio=1.0):
    """Train MBRSF for a given decision horizon T_C (censor at T_C first)."""
    T_capped = np.minimum(T, decision_horizon)
    delta_capped = delta & (T <= decision_horizon)

    X_min, T_min = X[minority_mask], T_capped[minority_mask]
    n_needed = max(int(target_ratio * (~minority_mask).sum()) - minority_mask.sum(), 0)
    X_s, T_s, d_s = survival_smote(X_min, T_min, n_synth=n_needed)

    X_bal = np.vstack([X, X_s])
    T_bal = np.concatenate([T_capped, T_s])
    d_bal = np.concatenate([delta_capped, d_s])

    y_bal = np.array([(bool(d), t) for d, t in zip(d_bal, T_bal)],
                      dtype=[('event', bool), ('time', float)])
    rsf = RandomSurvivalForest(
        n_estimators=1000, max_features="sqrt",
        min_samples_leaf=3, n_jobs=-1, random_state=42
    ).fit(X_bal, y_bal)
    return rsf


def hazardogram(rsf, X_episode, horizons):
    """Stack survival curves across multiple decision horizons for one episode."""
    grid = []
    for T_C in horizons:
        surv_fn = rsf.predict_survival_function(X_episode.reshape(1, -1))[0]
        times = np.linspace(0, T_C, 50)
        grid.append([surv_fn(t) if t <= surv_fn.x[-1] else surv_fn.y[-1] for t in times])
    return np.array(grid)

10. Test Yourself + Open Problems

Why is the near-Markovian assumption necessary here, when the original BRSF paper didn't need one?

A patient's full history is bounded (one lifetime, one record). A plant floor runs continuously and generates unbounded history per machine. Without the Markovian simplification (only current status + time-since-restoration matters), the state space would grow without bound and RSF couldn't be trained tractably.

Why does the paper report C-index and IBS separately per machine instead of one pooled number?

Different machines have very different roles (bottleneck vs. buffer stations) and very different breakdown rates — pooling would hide machines where the model quietly fails. Reporting per-machine also directly supports the "MBRSF is uniformly good, RSF is inconsistent" claim.

In the hazardogram, why do breakdowns cluster at the blue→red transition rather than deep in the red region?

Once the model is fully confident (deep red), the breakdown has essentially already become inevitable/imminent — real breakdowns happen at the transition because that's where the hazard is crossing the threshold from "unlikely soon" to "likely soon," which is exactly the moment of interest for early warning.

Why does "time since last restoration" dominate the influence graph over instantaneous status?

Instantaneous status is binary and noisy — a status flip can be a 2-second blip. Time-since-restoration integrates a machine's operating stress continuously, making it a smoother, more predictive signal of accumulated wear.

Genuine open problems (good portfolio/research extensions)

  • Learn the Markov order automatically — instead of assuming state depends only on current status + time-since-restoration, test whether adding a short window of recent history improves accuracy enough to justify the extra complexity.
  • Formalize survival-SMOTE for multivariate system states — interpolating 40-dimensional mixed binary/continuous vectors raises validity questions beyond the single-patient case.
  • Causal, not just correlational, influence graphs — permutation importance shows association; combine with intervention-style analysis (e.g. do-calculus, Granger causality) to test true cross-machine causal influence.
  • Online/streaming MBRSF — the paper trains on a full year and tests on the next; a streaming update rule would make this deployable in real time.
  • Uncertainty-aware hazardograms — add confidence bands to the heatmap so operators know when a "red" prediction is statistically shaky vs. solid.
