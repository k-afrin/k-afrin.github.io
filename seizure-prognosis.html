1. The Problem Why "Predict at a Fixed Time" Isn't Enough

Epilepsy affects an estimated 50 million people globally and elevates mortality risk by 1.6–9.3× versus the healthy population. The core clinical frustration: patients never know when the next seizure is coming. Prior seizure-prediction methods try to detect a "pre-ictal" (pre-seizure) state and then forecast a seizure at one specific future time — but:

"Even if a model says 'no seizure in the next 5 minutes,' a seizure happening at minute 3 can't be ruled out — because the model was never asked about minute 3."

This paper reframes the question entirely: instead of one prediction at one fixed horizon, estimate a full hazard function over the entire prediction window — the risk of seizure onset at every instant between now and the decision horizon. This is exactly what survival analysis (and RSF specifically) is built for.

4. Snowball Features Capturing Slow Build-up

Seizure precursors build up gradually — a single snapshot rarely shows an obvious warning sign, but the trend across snapshots does. The snowball feature captures exactly this: the accumulated change in a phase feature between two windows spaced 30 seconds apart.

—
$$ S(i) = x^{\varphi}(i) - x^{\varphi}(i-W), \qquad W = 30 \text{ sec} $$ Among the top 20 features selected by minimal depth, 14 of 20 were snowball features and only 6 were raw spectral features — the accumulated trend mattered more than any single snapshot.

5. The RSF Core Log-Rank Splits + Nelson-Aalen Hazard

Once features are extracted, RSF works exactly as in the original BRSF paper: grow trees by splitting on the feature/threshold that maximizes the log-rank statistic between daughter nodes, until each leaf has fewer than s₀ = 3 unique seizure events left. Drag ζ to explore a live log-rank split on synthetic seizure-onset-time data.

—
$$ \hat H_q(t) = \sum_{T_{l,q}\le t} \frac{d_{l,q}}{Y_{l,q}} $$ Once a leaf stops splitting, the Nelson-Aalen estimator gives that leaf's cumulative hazard curve. A sample's predicted risk is the ensemble average of its leaf's hazard across all B trees: $\hat H_e(t|x_i) = \frac{1}{B}\sum_b \hat H_b(t|x_i)$.

8. Implement It Yourself Python Skeleton

import numpy as np
from scipy.signal import stft, hilbert
from sksurv.ensemble import RandomSurvivalForest
from sksurv.metrics import concordance_index_censored, integrated_brier_score

def extract_spectral_features(eeg_segment, fs=4000, window_lengths=(1024, 2048, 4096)):
    """Extract STFT-based spectral energy features across 4 Hz bands, 0-50 Hz,
    for each window length, plus overall signal variance."""
    features = []
    for w in window_lengths:
        f, t, Zxx = stft(eeg_segment, fs=fs, nperseg=w)
        energy = np.abs(Zxx) ** 2
        band_edges = np.arange(0, 50, 1)  # 1 Hz step, 4 Hz bandwidth, overlapping
        band_energies = []
        for edge in band_edges:
            mask = (f >= edge) & (f < edge + 4)
            band_energies.append(energy[mask, :].sum())
        features.extend(band_energies[:17])  # ~17 bands per window length
    features.append(np.var(eeg_segment))  # signal variance feature
    return np.array(features)  # -> 52 spectral features total


def extract_phase_features(spectral_features):
    """Hilbert transform of the spectral-energy 'waveform' to capture
    shape/phase variation across frequency bands."""
    analytic_signal = hilbert(spectral_features)
    phase = np.angle(analytic_signal)
    return phase  # -> 52 phase features


def snowball_feature(phase_features_over_time, i, W):
    """S(i) = x_phi(i) - x_phi(i - W); captures accumulated change over W seconds."""
    return phase_features_over_time[i] - phase_features_over_time[i - W]


def build_training_sample(eeg_window, seizure_time_from_now, decision_horizon=300):
    """Construct one (x, T, delta) survival tuple for the RSF training set."""
    spectral = extract_spectral_features(eeg_window)
    phase = extract_phase_features(spectral)
    # snowball features would be computed using this window's phase vs one 30s earlier
    x = np.concatenate([spectral, phase])  # simplified; real version adds snowball features

    T = min(seizure_time_from_now, decision_horizon)
    delta = 1 if seizure_time_from_now > decision_horizon else 0  # censored if 1
    return x, T, delta


def train_rsf(X, T, delta):
    y = np.array([(bool(1 - d), t) for d, t in zip(delta, T)],
                 dtype=[('event', bool), ('time', float)])
    rsf = RandomSurvivalForest(
        n_estimators=1000, max_features="sqrt",
        min_samples_leaf=3,  # this is s0 = 3 from the paper
        n_jobs=-1, random_state=42
    ).fit(X, y)
    return rsf


def evaluate_rsf(rsf, X_train, T_train, delta_train, X_test, T_test, delta_test, horizon=300):
    y_train = np.array([(bool(1-d), t) for d, t in zip(delta_train, T_train)],
                        dtype=[('event', bool), ('time', float)])
    y_test = np.array([(bool(1-d), t) for d, t in zip(delta_test, T_test)],
                       dtype=[('event', bool), ('time', float)])

    risk_scores = rsf.predict(X_test)
    c_index = concordance_index_censored(y_test["event"], y_test["time"], risk_scores)[0]

    times = np.linspace(1, horizon-1, 50)
    surv_funcs = rsf.predict_survival_function(X_test)
    preds = np.array([[fn(t) for t in times] for fn in surv_funcs])
    ibs = integrated_brier_score(y_train, y_test, preds, times)

    return c_index, ibs

9. Test Yourself + Open Problems

Why does the paper deliberately avoid trying to define a "pre-ictal period"?

Because there's no clinically settled definition of when pre-ictal starts — any fixed definition is somewhat arbitrary, and a classifier's reported accuracy becomes an artifact of that choice rather than a property of the underlying EEG signal. Survival analysis sidesteps this by only requiring objective information: whether and when a seizure occurred, not what "stage" preceded it.

Why use snowball features instead of just the raw phase features directly?

Seizure precursors build up gradually — a single snapshot's absolute phase value may not look abnormal, but the *rate of change* over 30 seconds captures the slow, subtle drift that single-snapshot features miss. This is empirically confirmed: 14 of the top 20 features selected were snowball features.

Why is minimal depth (MD) preferred over VIMP for feature selection here?

VIMP measures importance via how much prediction error increases when a feature is "noised up" — this is sensitive to whatever biases already exist in the trained model. MD instead measures how close to the root node a feature tends to cause splits, which is a structural property of the trees themselves and considered more robust to model bias.

Why does sensitivity/specificity improve as the model looks closer to the actual seizure onset (Table 3)?

The EEG signal's precursor signature (frequency shifts, snowball trends) becomes more pronounced the closer you are to the actual seizure — so short-horizon predictions have a stronger, less noisy signal to work with than long-horizon ones.

Genuine open problems (good portfolio/research extensions)

  • Human validation — the paper explicitly notes this is animal (rodent) data via an organophosphate-intoxication epilepsy model; translating to human intracranial or scalp EEG is future work the authors flag directly.
  • Longer decision horizons — the 300-sec horizon was chosen based on the average inter-seizure interval in this dataset; systematically studying how RSF performance degrades as T_D grows is open.
  • Exogenous factors — the paper notes environmental/exogenous influences on seizure timing are not yet incorporated; adding them (sleep state, medication timing, time of day) is a natural extension.
  • Graph-based coupled dynamics features — the authors mention ongoing work using random-graph representations of coupled EEG channel dynamics as a richer feature set beyond single-channel spectral/snowball features.
  • Adaptive, risk-informed alert thresholds — the current 0.69 survival-probability threshold was fixed to balance sensitivity/specificity; a patient-adaptive or cost-sensitive thresholding scheme is an open design question for a real seizure warning system.
