4. How a Tree Actually Splits The Log-Rank Statistic, Live

At every node, RSF scores candidate splits with the log-rank statistic — the same test statistic from biostatistics, repurposed as a splitting criterion. Drag ζ across the biomarker axis; the computed statistic uses the real two-sample log-rank formula on this synthetic cohort.

—
Died Censored
$$ L(x_v,\zeta) = \frac{\sum_l \left(d_{l,1} - Y_{l,1}\frac{d_{l,q}}{Y_{l,q}}\right)} {\sqrt{\sum_l \frac{Y_{l,1}}{Y_{l,q}}\left(1-\frac{Y_{l,1}}{Y_{l,q}}\right)\frac{Y_{l,q}-d_{l,q}}{Y_{l,q}-1}d_{l,q}}} $$ Numerator = "observed deaths on the left minus deaths expected by chance." Bigger |L| = better split.

5. Why Imbalance Breaks This The Paper's Core Insight

Every leaf must keep at least $d_0$ unique deaths (here, 3). When the minority (death) class is rare, its leaves get starved to almost nothing — and their hazard estimate plateaus before it should. 6. The Fix: SMOTE Synthetic Minority Over-sampling

Instead of duplicating rare patients (teaches the model nothing new) or discarding common ones (wastes data), SMOTE invents new, plausible minority patients by interpolating between real ones and their nearest minority neighbors. Click to generate some and watch where they land.

Synthetic samples created: 0
Majority (survivors) Minority (real deaths) Synthetic (SMOTE-generated)
$$ x_{new} = x_i + \gamma\,(x_j - x_i), \qquad \gamma \sim \text{Uniform}(0,1) $$ where $x_j$ is a randomly chosen nearest minority neighbor of $x_i$.
⚠️ Open gap in the paper: this formula only interpolates features. It never specifies how synthetic $(T,\delta)$ pairs are generated for survival time — a genuine ambiguity, and a good place to make an original contribution (see §10).

9. Implement It Yourself Python Skeleton

A minimal, runnable core using scikit-survival, mirroring the algorithm simulated in the demos above.

import numpy as np
from sklearn.neighbors import NearestNeighbors
from sksurv.ensemble import RandomSurvivalForest
from sksurv.metrics import concordance_index_censored, integrated_brier_score

def survival_smote(X_min, T_min, k=5, n_synth=100):
    """Standard SMOTE, adapted for survival time.
    NOTE: the paper never specifies synthetic (T, delta) generation --
    this is an open design choice (see the SMOTE section above)."""
    nn = NearestNeighbors(n_neighbors=k+1).fit(X_min)
    _, nbrs = nn.kneighbors(X_min)
    X_syn, T_syn = [], []
    for _ in range(n_synth):
        i = np.random.randint(len(X_min))
        j = nbrs[i, np.random.randint(1, k+1)]
        g = np.random.uniform(0, 1)
        X_syn.append(X_min[i] + g * (X_min[j] - X_min[i]))
        T_syn.append(T_min[i] + g * (T_min[j] - T_min[i]))
    return np.array(X_syn), np.abs(np.array(T_syn)), np.ones(n_synth, dtype=bool)

def train_brsf(X, T, delta, minority_mask, target_ratio=1.0):
    X_min, T_min = X[minority_mask], T[minority_mask]
    n_needed = max(int(target_ratio * (~minority_mask).sum()) - minority_mask.sum(), 0)
    X_s, T_s, d_s = survival_smote(X_min, T_min, n_synth=n_needed)

    X_bal = np.vstack([X, X_s])
    T_bal = np.concatenate([T, T_s])
    d_bal = np.concatenate([delta, d_s])

    y_bal = np.array([(bool(d), t) for d, t in zip(d_bal, T_bal)],
                      dtype=[('event', bool), ('time', float)])
    rsf = RandomSurvivalForest(
        n_estimators=1000, max_features="sqrt",
        min_samples_leaf=3,   # <-- this is d0 from the paper
        n_jobs=-1, random_state=42
    ).fit(X_bal, y_bal)
    return rsf

10. Test Yourself + Open Problems

Why does under-sampling the majority hurt survival analysis more than plain classification?

With few total samples, you lose the ability to resolve a fine-grained hazard curve at all — every leaf becomes noisy, not just the minority-class ones. Survival curves need many observed event times, not just class labels.

If d₀ increased from 3 to 10, would the underestimation bias get worse or better?

Worse. Larger d₀ forces bigger "reserved" minority leaves, truncating the usable hazard curve earlier — exactly what the bias demo above shows.

Why evaluate BRSF on the original imbalanced test set, not a balanced one?

Because the real world stays imbalanced. Balancing is a training-time fix for a biased learning signal — testing on synthetic data would just measure how well you memorized your own interpolation.

What happens to L(x_v, ζ) if a split perfectly separates all deaths left, survivors right?

|L| is maximized — the log-rank statistic measures deviation from "no difference between groups," and perfect separation is the most extreme deviation possible.

Genuine open problems (good portfolio/research extensions)

  • Survival-aware SMOTE — formally define and benchmark how synthetic (T, δ) should be generated.
  • Beyond one split — extend the bias proof to realistically deep, correlated trees.
  • Alternative resamplers — Borderline-SMOTE, ADASYN, SMOTE-ENN untested in this setting.
  • Competing risks — generalize beyond binary censored/event to multiple rare causes of death.
  • Cost-sensitive splitting — reweight the log-rank statistic directly instead of resampling, avoiding the synthetic-time problem entirely.
  • Deep survival models — test whether DeepSurv/DeepHit show the same imbalance bias, and whether the same fix helps.
